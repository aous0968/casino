# ADR 0002: HS256 for now, RS256 later

## Context

All services need to verify JWTs. With HS256, verification requires the same
secret that signs, so any service with the secret can also forge tokens.

## Decision

Start with HS256 for simplicity. Structure the code so Signer and Verifier
are distinct types. When we split services across trust boundaries, migrate
to RS256: auth-service holds the private key; everyone else holds the public.

## Consequences

Until the migration, the JWT secret must be treated as a critical secret
shared by every service. Rotating it invalidates every session.
